# Working on Argent

**Argent is strictly an in-development project. It is NOT in production. Backwards compatibility is not a requirement.** Breaking changes to APIs, schemas, stored definitions, and internal interfaces are acceptable. Prefer a clean implementation over compatibility shims, legacy branches, or migration machinery whose only purpose is preserving old behavior. Keep database initialization and development seeding working; explain any required database reset.

- Read `ARCHITECTURE.md` for the project map, then verify the relevant code. Follow existing patterns and keep changes focused. Preserve unrelated work already in the workspace.
- Respect project boundaries: `Argent.Core` holds shared models/contracts; `Argent.Infrastructure` holds EF mappings/migrations; `Argent.Runtime` implements application services; `Argent.Web` hosts APIs and Razor Pages; `Argent.WebComponents` holds Blazor designers; `Argent.Web.Client` hosts WebAssembly; `Argent.FormRuntime` is the Svelte/TypeScript form renderer.
- Run the application through **`Argent.Host`**, which starts SQL Server, the web app, and the workflow engine. Starting only `Argent.Web` does not start its dependencies. Use `dotnet run --project Argent.Host/Argent.Host.csproj --launch-profile https`; Docker must be available. Rebuild before using `--no-build`.
- Build affected projects and run relevant checks. .NET tests live in `Argent.Runtime.Tests` and `Argent.WebComponents.Tests`; use `dotnet test <project>`. In `Argent.FormRuntime`, use `npm run check`, `npm test`, and `npm run build` when relevant. Test production code rather than copied implementations.
- For interaction changes, verify in Playwright against the current build. Check Chromium and Firefox when behavior differs between browsers. Use disposable or unsaved workflows/forms for testing: designers autosave. Measure performance before claiming an improvement.
- Trace changes through persistence, APIs, designers, runtime rendering, and validation where applicable. Update architecture documentation when responsibilities or important data flows change. Report what changed, what was verified, and any remaining limitation.
